# Windows island localization

The Windows island uses the existing `t` / `setLocaleTable` API. No extra
localization library or runtime translation service is required.

## Catalogs

The 15 macOS languages are English (US), Português (Brasil), Türkçe, Русский,
Español, Slovenčina, Deutsch, Français, Italiano, 日本語, 한국어, Українська,
简体中文, 繁體中文（台灣）, and 繁體中文（香港）.

`src/i18n/generated/<language>.json` is generated from the actual Swift tables
under `Sources/Vorssaint/Core`. It preserves accessor/field names, Unicode,
punctuation and printf placeholders. The tokenizer handles literal initializers,
aliases, grouped switch cases and literal word-array constructors. Unresolved
island fields fail extraction. The builder-only WhatsApp downloads table is
excluded because Windows does not use it. No macOS source is modified.

From `windows/`, with Python 3 available:

```sh
npm run i18n:extract
npm run i18n:check
npm run test:i18n
npm run test:i18n-ui
```

`I18N_PYTHON` can specify the Python executable. Python is a development tool,
not an application dependency. Extraction also updates `keys.d.ts`, the small
native-menu subset `native.json`, and `extraction-report.json`. After adding a
Windows-only key, `node scripts/i18n-extract.mjs --keys-only` updates the types.

`overrides/<language>.json` supplies Windows-only labels and text where the Mac
table is English-only (including sessions). Existing translated Mac values are
reused wherever a matching value exists. Windows-only additions were translated
with Microsoft Translator and have not received a complete human linguistic
review. Taiwanese and Hong Kong overrides share Traditional Chinese terminology;
the imported Mac catalogs retain their distinct regional translations. English
is the fallback for missing values. Keep override keys identical across all
languages and run `i18n:check` to verify placeholder compatibility.

`source-map.json` records the source-to-key migration, and the AST inventory
checks remaining UI literals. This audit is intentionally scoped to UI text;
technical identifiers, shortcuts, product names, URLs, user content and external
application/OS error details retain their original values. `localizeMessage`
must only be used for application-generated messages, never user content.

## Runtime and persistence

Every webview initializes localization before rendering. The existing saved
`island.language` preference supports `auto` plus the 15 language identifiers.
The Settings picker applies changes immediately and uses the existing atomic
Rust preference persistence and `prefs://changed` broadcast. React consumers
subscribe through `useLocale`; switching does not remount the island, reset
animations, or discard input drafts. Out-of-order asynchronous loads cannot
override the newest selection.

Automatic selection follows the Mac language-prefix rules, including distinct
Hong Kong / Taiwan / Simplified Chinese choices. Native Windows regional
settings provide preferred UI language, region, hour cycle and first weekday.
Date/number formatting combines UI language with those regional settings.
`WM_SETTINGCHANGE` with `intl` refreshes formatting and automatic language
selection. Native tray items, window titles and screenshot-save labels use the
small generated subset of the same catalog.

Use `tf(key, ...arguments)` for Swift printf templates; `t(key)` keeps literal
filename templates untouched. `pluralForm` follows the Mac count rules rather
than assuming English or CLDR zero behavior. The catalog check verifies printf
argument types, counts and positional references for every language.

## Verification scope

Unit tests cover all catalog loads, fallback, saved preferences/broadcasts,
automatic detection, racing language changes, formatting and plural rules.
The Edge test exercises every language in the real Settings picker, live title
updates, viewport fit and island switching while preserving a session draft.
These checks do not constitute native-speaker review or manual coverage of
every feature in every language. Test Windows regional-setting changes on a
machine where changing the OS setting is appropriate. The optional Swift
compiler/Mirror validation described in the specification requires macOS.
