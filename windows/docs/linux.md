# Linux (X11)

The island runs on Linux under X11 (tested on XFCE with xfwm4 and picom). Wayland is not supported yet.

## Build

You need [Bun](https://bun.sh), [Rust](https://rustup.rs) and the Tauri system libraries (`webkit2gtk-4.1`, `gtk3`, `libayatana-appindicator`, `librsvg`, `openssl`, `xdotool`). To run it, reading text from the screen needs `tesseract` (with the data of your languages) and sound also needs `pactl` and `parec` (the `libpulse` package on Arch and Fedora, `pulseaudio-utils` on Debian and Ubuntu, with PulseAudio 16 or later or PipeWire's pulse server)), and the screen recorder needs `ffmpeg` (built with x11grab, libx264, AAC and PulseAudio input, as distributions build it). Then, in `windows`:

```sh
bun install --frozen-lockfile
bun run build
cd src-tauri
cargo build --features tauri/custom-protocol   # embeds ../dist; without it the app loads the dev server
```

Packages: `bun run tauri build --bundles deb,rpm,appimage` (the config's own target list is the Windows installer).

## What works

- The island window: transparent, always on top, a dock window that takes no focus. The window is cut to the island's shape (XShape), so clicks anywhere else go to the windows below, which also works under xfwm4. A compositor that blurs behind windows (picom) blurs the whole cut, so the cut follows what is drawn, not where the island is going, and is exactly the painted shape (a notch's ears included, with no margin), or the blur would show as a frosted outline around the island; the round buttons grow in without fading.
- Claude Code sessions, read from `~/.claude/sessions` through `/proc`. Hooks reach the island over a socket in `~/.openbar` (in the temp folder when the home folder's path is too long for a socket address).
- Open and Reply (tmux, kitty and WezTerm are covered by tests against stand-in programs, not run against the real ones): Open raises the terminal's window through the window manager (`_NET_ACTIVE_WINDOW`). Replies go into tmux (`$TMUX`, `$TMUX_PANE`; the pane must be on the session's own terminal, since an editor opened from a pane keeps both), kitty (needs `allow_remote_control` and `listen_on`; the window must list the session's process), WezTerm (`wezterm cli`) and VS Code, Cursor, Antigravity and Windsurf through the bridge extension. Any other terminal is raised, not typed into.
- The island hides while a fullscreen app is active (`_NET_WM_STATE_FULLSCREEN`), and "All displays" puts a mirror on each other monitor.
- Now playing (`media.rs`): any player on the session bus that speaks MPRIS (Spotify, VLC, Rhythmbox, a browser tab, ...), with its cover, seek, shuffle, the source menu and Open player (raises the player, or starts it from the applications menu). The Spotify queue is read through Windows accessibility and has no Linux counterpart. Covers come from files and HTTPS, through the web view's own HTTP library (libsoup).
- Sound (`audio/`): the Mixer and Controls over the sound server (PulseAudio, or PipeWire's pulse server) through `pactl`: the output's and microphone's level and mute, the default device, every app that plays with its own level, Mic Mute, audio priority, the headphone guard, the output switcher and the finer volume keys. An app counts as playing while its stream is not paused. The Music page's player volume and the spectrum next to the song work too; the spectrum records the player's own stream with `parec`. The microphone indicator shows when an app records from a microphone (it reads the server's lists and never records, so it has no level meter).
- Icons and names (`shell.rs`): the icon theme and the desktop entries give app icons, file icons and thumbnails, and the system monitor opens from the System page.
- Power (`battery.rs`, `power_saver.rs`, `session_lock.rs`, `keep_awake.rs`): the machine's own batteries from `/sys/class/power_supply` (charge, charger, rate, time left, wear and cycles; a mouse's battery or a UPS is left out), the energy saver as power-profiles-daemon's `power-saver` profile, the unlock of the session (from systemd-logind, a screensaver service, or a screen locker program such as `xsecurelock` or `i3lock` that was running and ended), and Keep Awake through logind's inhibitor and the desktop's power manager.
- Brightness (`brightness.rs`): a panel's backlight, written through logind, and external displays over DDC/CI with `ddcutil` (which needs the `i2c` group).
- Quick toggles (`toggles.rs`): lock the screen, turn the display off (X11 power management), start the screensaver, empty the trash, and dark mode on GNOME-family desktops. Hidden files, desktop icons and ejecting disks differ too much between desktops and are not offered.
- Notifications (`notifications.rs`): there is no list of other apps' notifications to read on Linux, so the island listens to the calls apps make to the notification service (a monitor connection to the session bus, as `dbus-monitor` does; the desktop's own popup still shows). It keeps the title, text and icon of what arrives while it runs, folds an app's updates of one notification into one entry, and leaves out transient ones and the volume and brightness displays. Open starts the app the notification came from.
- System (`system_monitor.rs`): CPU, memory (with swap, cache and zram), network, disk space and activity, the GPU (`nvidia-smi`, or an AMD card's busy file), battery, uptime and connected USB and Bluetooth devices, read from `/proc`, `/sys` and BlueZ, with the CPU, memory and GPU (NVIDIA) process lists grouped by program. Network traffic and power by process need privileges or a trace, so those lists say they are unavailable.
- Clipboard (`clipboard/`): the history of copies (text, files and pictures, in that order of preference) through GTK's clipboard, which tells when its owner changes. A copy a password manager marks as secret (`x-kde-passwordManagerHint`) is left out, the app a copy came from is the clipboard's owner or else the window in front, and Paste types Ctrl+V (Ctrl+Shift+V in a terminal) into the window in front through the X server's test extension. Needs a window manager that keeps `_NET_ACTIVE_WINDOW`, as every desktop one does.
- Calendar (`calendar.rs`, `ics.rs`): Linux has no one store of appointments, so the system's events are read from calendar files: `.ics` files in `~/.local/share/openbar/calendars`, Evolution's local calendars, and the folders vdirsyncer and khal keep (a folder of `.ics` files is a calendar, named and colored by its `displayname` and `color`). Repeating events are expanded (daily, weekly, monthly and yearly rules with their usual parts, exceptions and changed occurrences). Events made in Openbar work as on Windows. Evolution Data Server, KDE's Akonadi and online accounts are not read; syncing them to files (vdirsyncer) is how they get in.
- Screen capture (`capture/`, `ocr.rs`): the screenshot, Copy text from screen and colour picker tools take the picture of the screen from the X server (`GetImage` of the root window), find the display under the pointer with RandR and the window under a point from the window manager's stacking list, and put pictures and text on the clipboard. Reading text uses Tesseract (`tesseract` with the language data of your locale, and English). A screenshot is dragged out of its preview as a file, the way a Shelf tile is. Sharing is a Windows feature and is not offered.
- Background sessions (`sessions/background.rs`): Claude Code's and Codex's own commands run with no window (`claude agents` lists the background agents); a new session or an attach opens in the first terminal found (`$TERMINAL`, then GNOME Terminal, XFCE Terminal, Konsole, kitty, Alacritty, WezTerm, foot and others); a reply to a background session is typed into `claude attach` on a pseudo-terminal nobody sees.
- Alerts: the timer's and Watch's chime is played through `paplay`, `pw-play`, `aplay` or `ffplay`, whichever is found first, and the timer counts time since boot (`CLOCK_BOOTTIME`), so a timer that ran out while the PC slept rings when it wakes.
- File actions (`files/shell.rs`) and Downloads (`downloads.rs`): Open starts a file with the app the desktop has for its type, Open With lists the apps that can open every selected file, Show in file manager asks `org.freedesktop.FileManager1` to select the files (or opens the folder when no file manager answers), and Delete moves a file to the trash. The Shelf's items, pins and ZIP archives are plain file handling. Dragging works through GTK's own drag and drop on the island's web view (`shelf.rs`): files, links and text dragged onto the island go on the Shelf, as they do through Windows' drop target, and a tile is dragged out as the files (a URI list, which file managers, editors and browsers take) or as text (a link goes out as its address). A drag that starts in the page itself, such as a text selection, is left to the page. The downloads list watches the desktop's Downloads folder and the folder each Chromium browser profile or Firefox profile is set to save in, and follows the browsers' temporary files (`.crdownload`, `.part`). Sharing is not offered, since Linux has no Share sheet.
- AI Agents usage (`agent_usage/`): Claude Code's, Codex's and Copilot's logs are read from `~/.claude`, `$CLAUDE_CONFIG_DIR`, `~/.config/claude`, `~/.codex` and `~/.copilot`, and a Claude session counts as running by its record in `sessions/`, which Claude Code on Linux writes with the machine and namespace in its `pidDomain`. Checked with `--agents-probe` against this machine's own logs (106 files, 26 thousand records); Codex and Copilot are covered by the shared parser's tests, there were no logs of theirs to read. The plan limits come from the vendors' command line tools and were not tried. OpenCode's database and the daily price list are Windows-only reads, so OpenCode is not counted and prices are the ones built in.
- Language and regional formats (`locale.rs`): the UI language follows `LC_ALL`, `LC_MESSAGES` or `LANG` (with `LANGUAGE` leading, as gettext has it, and the C locale meaning English), the region and 12 or 24 hour clock follow `LC_ALL`, `LC_TIME` or `LANG` (the clock format is the C library's, so the locale must be installed), and the week starts on Sunday in the regions that start it so, Monday elsewhere.
- Screen recorder (`recorder/`): the Record tool grabs the chosen area with `ffmpeg` (x11grab), takes the system's sound from the default output's monitor and the microphone from the default input, mixes them, and writes an H.264 and AAC MP4 into the Videos folder. Stopping tells ffmpeg to close the file, and a file it could not close is not offered. The island is part of the screen, so it is in a recording when it is in the area (X11 cannot leave a window out of a capture).
- Global shortcuts, tray icon (its menu; a plain click does not open Settings, the tray protocol has no click event), launch at login (`~/.config/autostart/openbar.desktop`).
- Settings and caches live in `~/.config/com.openbar.island` and `~/.cache/com.openbar.island`.

## Where the code is

Everything Linux does differently is in `src-tauri/src/linux/`, a file for each piece of Windows code it stands in for: the window (`island.rs`), fullscreen (`fullscreen.rs`), launch at login (`autostart.rs`), processes from `/proc` (`process.rs`), terminals and editors (`hosts.rs`, `tmux.rs`, `kitty.rs`, `wezterm.rs`, `x11.rs`, `command.rs`, `ide.rs`), session records (`sessions.rs`), hooks (`hooks.rs`), the XDG folders (`paths.rs`), now playing (`media.rs`), power and brightness (`battery.rs`, `power_saver.rs`, `session_lock.rs`, `keep_awake.rs`, `brightness.rs`, `toggles.rs`), notifications (`notifications.rs`), the System page (`system_monitor.rs`), the clipboard (`clipboard.rs`, `gtk_main.rs`), the calendar (`calendar.rs`, `ics.rs`), screen capture (`screen.rs`, `ocr.rs`), background sessions (`background.rs`), the alert chime (`sound.rs`), sound (`audio.rs` and `pulse.rs`, with `microphone.rs` and `music_levels.rs` for the indicator and the spectrum), icons (`shell.rs`, `image.rs`, `desktop.rs`) and the file actions, downloads folders and dragging (`files.rs`, `downloads.rs`, `shelf.rs`), the locale (`locale.rs`) and the screen recorder (`recorder.rs`). The Windows modules only hand over to these with `cfg(target_os = "linux")`, and the code Windows compiles is otherwise as it was. A new Linux piece is a new file there and one hand-over where the Windows module has its own.

## NVIDIA

WebKitGTK cannot back its GBM buffers on the proprietary driver and leaves every page blank. The app sets `WEBKIT_DMABUF_RENDERER_FORCE_SHM=1` when `/proc/driver/nvidia/version` exists, unless one of the `WEBKIT_DMABUF_RENDERER_*` or `WEBKIT_DISABLE_DMABUF_RENDERER` variables is already set. `WEBKIT_DISABLE_DMABUF_RENDERER=1` alone does not draw the island's body.

## Not done yet

- Wayland. The island needs a layer-shell window (`gtk-layer-shell`), the global shortcuts, the screen capture and the clipboard each need a portal or a compositor protocol, and none of that can be tried without a Wayland compositor, which this was developed without. Nothing in the Linux code claims to work there.
- "Show in screenshots": X11 has no way to keep a window out of a capture, so the setting does nothing and the island shows in screenshots other programs take (Openbar's own screenshot tool takes its picture before its overlay is shown).
- The toolkit sections that read Windows APIs and are not ported yet: the browsers' own download records (the downloads list sees files, not the pages they came from), voice replies, Watch, the speed test, the Discord mute reading, and OpenCode's usage and the daily price list in the AI Agents section.
